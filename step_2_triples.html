Step 2 — triples pipeline (gpu_bundle)

Order of execution, inputs and outputs of the Python scripts in lung/gpu_bundle/ — the Kaggle/GPU bundle that takes the NER corpus handed over by step 1 (experimental_ner/) and turns it into normalized, learned-scored relation triples. One orchestrator, gpu.py, runs a fixed 20-step chain in dependency order; each step is a standalone script run as a subprocess in a single writable working directory, and the final step zips that directory into one downloadable archive.

You normally run one command — python gpu.py — and it executes all 20 steps for you, in the order below, in one staged working directory (/kaggle/working/ on Kaggle, or in place locally). It is not a loose set of scripts you run by hand: gpu.py copies the scripts, symlinks the read-only experimental_ner/ corpus, makes a writable copy of databases/, creates the output dirs (GENETIC/ DISEASE/ CHEMICAL/ TRIPLES/, plus sentences/ and summaries/), and sets RE_MODEL_PPI and RE_MODEL_BIORED for the learned RE step. Steps 1, 2, 4 and 17 use CUDA; steps 1–4 and 16 reach the network. Steps 1–2 are gated: they train only when the previous training output is not already in the bundle, so on every run after the first the chain effectively starts at step 3 (see the box under section 1A). Steps 2, 3, 15, 16, 18 and 19 are optional — if they fail the orchestrator warns and continues. The last step (zip_work.py) bundles the whole working directory into kaggle_working.zip so the entire run is a single download. Run a subset with --steps a,b,c and preview the plan with --list.

The training gate — why steps 1–2 usually do not run. Neither step reads the corpus: both fine-tune BioBERT on a fixed public BigBIO dataset, so each checkpoint is a function of (dataset, seed, hyperparams) only and is identical for every corpus this pipeline is pointed at. All four complete → steps 1 and 2 are dropped from the plan and the checkpoints on disk are staged and exported to step 17 as they are. Any file being empty counts as missing, so a half-copied bundle retrains rather than loading a truncated checkpoint.

It is all four or none by design: step 17 routes between the two checkpoints and step 18 compares them, so a run must never mix a reused PPI model with a freshly trained BioRED one (or the reverse) — the comparison would be measuring two generations against each other. The *_data/ TSVs are gated alongside the checkpoints because they are what makes a reused bundle re-calibratable without going back to Hugging Face.

Steps 5–12 all read the same sentences/*.json and only touch their own type's library dir, so gpu.py runs them as three lanes side by side — GENETIC (5→8), DISEASE (9→10), CHEMICAL (11→12) — and keeps the order within each lane (NORM_PARALLEL_CPU=0 runs them in turn): roman.py (step 5) builds the GENETIC libraries that greek.py/keys_values.py/controls.py extend or report on; controls.py (8) re-annotates those libraries in place, so it runs after roman.py/greek.py rewrite them. target_pharm.py (13) waits for all three lanes. triples.py (14) reads all three finished libraries; relationships.py (15) reads triples.py's output; pub_years.py (16) reads every triples file present, genetic_genetic.json included. The learned RE step (17) depends only on the step 1–2 models and step 4's sentences, so it is independent of the 15–16 branch. compare_re.py (18) reads only step 17's output and needs both checkpoints to have been produced, so it is skipped when step 2 did not run. triples_per_year.py (19) reads step 17's normalized triples and step 16's year cache.

3. How to run

  1. 1python gpu.py --list — preview the plan (roots, input count, accelerator, the training-gate verdict, the steps that will actually run).
  2. 2python gpu.py — run the chain end-to-end: all 20 steps on a first run, 18 once the gate finds the trained artifacts in place. On Kaggle: enable the GPU accelerator + internet, and !pip install -q 'datasets<4' bioc first (needed only for the BigBIO downloads in steps 1–2, i.e. only when the gate lets them run).
  3. 3python gpu.py --retrain — train even though the artifacts are complete (new hyperparameters, a corpus version bump, a checkpoint you no longer trust).
  4. 4python gpu.py --steps triples,relation_extraction — run a subset (e.g. re-derive triples from existing sentences/ and libraries).

Individual scripts can still be run directly (python triples.py, etc.) — each resolves its paths relative to its own file — but gpu.py is the intended entry point because it stages inputs, orders the steps, and wires up RE_MODEL_PPI and RE_MODEL_BIORED.

Steps 1–2 (run_re_pipeline.py) need internet + datasets<4 to download BigBIO bioinfer and biored; step 3 (drug_lexicon.py) downloads the NCI Thesaurus; step 4 (sentences.py) pulls the BioBERT NER models from Hugging Face on first use; step 16 (pub_years.py) calls NCBI for whatever pmids/pmid_pmc_ids.tsv does not cover. Steps 1, 2, 4 and 17 run on CUDA (they fall back to CPU — slow — if no GPU is visible). Those two network dependencies apply only when the training gate lets steps 1–2 run: ship ppi-biobert-re/ + ppi_data/ + biored-biobert-re/ + biored_data/ with the bundle and the gate skips them by itself — no --steps, no datasets<4/bioc, no internet for that phase. Upload sentences/ and skip step 4 the same way to reuse a prior NER pass, and databases/ncit_drugs.json + databases/pmc_years.json to run steps 3 and 16 without internet. Skipping step 2 without supplying its checkpoint also disables step 18.

4. Notes

  • One orchestrator, one working dir. gpu.py stages the scripts, experimental_ner/ (symlinked), a writable databases/ copy, and the output dirs into a single run root, then runs each step there as a subprocess with the same environment.
  • The hub file is sentences/*.json. Step 4 produces it from the XML corpus; steps 5–14 and 17 all read it. Three parallel normalization branches (GENETIC / DISEASE / CHEMICAL) fan out from it and reconverge in triples.py.
  • Two triple producers. triples.py (14) is rule-based (relation-cue text between consecutive entities); relation_extraction.py (17) is the trained BioBERT model. Both write into TRIPLES/; step 17's scores are the learned counterpart to step 14's candidates.
  • Two relation models, scored additively. Steps 1 and 2 train the same architecture on different corpora — BioInfer (binary “interacts”, sentence-scoped, cleanly labelled) and BioRED (typed and signed, document-level annotation). Step 17 runs both over every applicable pair rather than picking one, step 18 compares them, and the replace-or-not decision is deferred to the graph step, where --merge union|gate|typed|none chooses the policy. Nothing in the bundle commits to one model.
  • Normalization is layered. triples.py writes the base triples then three progressively normalized files: +HGNC, +MONDO, +ChEBI — the last (triples_GENETIC_DISEASE_CHEMICAL_normalized.json) is the fully ID-normalized set.
  • In-place annotators. controls.py (8), phenotypes.py (10) and nonchemical.py (12) add yes/no flags onto existing library JSON rather than producing new corpora — so they must run after the libraries they annotate are built.
  • Hand-off from step 1. The input experimental_ner/ is exactly what the publications pipeline (step_1_publications.html) assembled; this bundle is the "step 2" referenced there.
  • Single-download bundle. The last step, zip_work.py (20), packs the whole working directory into kaggle_working.zip — so the entire run (model, sentences, normalization libraries, TRIPLES/ and the HTML summaries) comes off Kaggle as one file. It runs after every other step, and builds the archive in a temp dir so the growing zip can't include itself.

5. What the 3 training epochs bought (measured, 2026-08-02)

train_re.py --epochs defaults to 3.0 (train_re.py:228, passed through by run_re_pipeline.py:474) and both checkpoints kept their checkpoint-*/trainer_state.json, so the per-epoch dev curve is recoverable without retraining. load_best_model_at_end evaluates once per epoch and selects on dev F1.

NER is not trained here — it gets zero epochs. The “three fine-tuned BioBERT NER models” in the step-4 row above were fine-tuned by their authors; this pipeline runs them frozen through the Transformers token-classification pipeline (sentences.py:255-263). There is no train_ner.py, no NER dev split and no NER checkpoint in the bundle. Every epoch count on this page refers to relation extraction only.

The epochs and the calibrator are the same story told twice. BioRED's eval loss rose 35% (1.11 → 1.50) across the three epochs while F1 improved. That divergence is the model becoming more confident faster than it becomes more correct — and it is exactly what produced the raw ECE of 0.2761 that section 6 has Platt undo. The fitted a = 0.3878 is, in effect, dividing the logits by ~2.6: stripping back out the overconfidence epochs 2–3 put in. Cutting BioRED to two epochs would cost ~0.9 F1 and start from a better-calibrated model; keeping epoch 3 and letting the calibrator clean up is the better trade, but only because the calibrator runs. The two settings should not be changed independently.

Note the dev eval_f1 above and the 0.6601 in summaries/calibration.html are different metrics — the latter is micro-averaged over positive classes only, on test, at a decision threshold of 0.2653 tuned on dev. They are not comparable figures.

6. Calibration: how much it changes, and what it does not (measured, 2026-08-02)

calibration.py maps each model's raw softmax to a probability. (Historic: this was resolved per task — isotonic for ppi, Platt for biored. Everything measured below describes that arrangement, which is what produced the triples currently in TRIPLES/. Recommendation 2a moved every task to Platt.) The calibrated value feeds p_rel in the composite score (score = p_rel × ner × cue × margin × section × self_pair, clamped to [0,1] at relation_extraction.py:565). Because the composite is multiplicative and each triple records both the raw predicate.score and the calibrated score_components.p_rel, the RE_CALIBRATE=0 pipeline can be reconstructed exactly — score_raw = score_cal / p_rel_cal × p_raw — without re-running the GPU step. Everything below comes from that ablation over the 1,247-triple corpus.

Un-calibrated, the composite clamps at 1.0 and the scores pile up on the ceiling: 53% of BioRED triples (512 of 967) and 42% of PPI triples (118 of 280) land at exactly 1.000. Calibrated, that is 0 and 40 respectively. The ≥0.99 slider stop would select 57% of the corpus instead of 4.5%. This is the whole case for calibration: every threshold in the pipeline is an absolute number (--score, --thresholds, the 0.5–0.99 browser slider), and against raw softmax those numbers point at nothing. Threshold by rank or percentile instead and calibration becomes a genuine no-op.

The weak point: the two calibrators are not on one scale

--merge union takes max() of the two models' scores for a pair both claim. That is a cross-model comparison, and it is where miscalibration actually bites.

Calibration did not remove a cross-model bias here — it created one. Platt on BioRED is aggressive (a=0.3878, b=-1.2197: raw 0.99 → 0.637, 0.999 → 0.811), and its highest composite anywhere in the corpus is 0.9022 — so no BioRED triple can ever reach the ≥0.95 slider stop. PPI's isotonic saturates at exactly 1.0. Under union the PPI verdict therefore wins the score almost always, and the typed model — which supplied 948 of 1,159 labels — is structurally locked out of the high-confidence view.

The PPI isotonic is the weaker of the two. 197 breakpoints collapse onto just 8 distinct output levels — 0.0, 0.5556, 0.6667, 0.6923, 0.8077, 0.8529, 0.9756, 1.0 — with an 82-breakpoint plateau at 0.9756. It quantizes PPI scores into eight buckets (45 triples on 0.692, 32 on 0.808), and it emits a hard 1.0 and a hard 0.0, asserting certainty from a 780-row dev split. BioRED_task_mapping.md:324-331 argues isotonic “overfits small calibration sets badly… will fit a step function to a few hundred points” and switches BioRED to Platt on that basis. The staircase above is that exact failure, on the PPI side, where the argument was not applied.

Fixed both ways (recommendations 2a and 3): the default calibrator is now Platt for every task, and calibration.py clips every output into [CLIP, 1−CLIP] with CLIP = 1e-3 at fit and apply time. Passing the existing, unmodified ppi-biobert-re/calibration.json through the new code now yields 0.0010 at the bottom and 0.9990 at the top instead of 0.0 and 1.0 — no refit required, though the scores already in TRIPLES/ keep the old values until the RE step runs again.

The per-task calibrator table in BioRED_task_mapping.md was marked superseded in the same pass, with the reasoning kept — leaving it to say “isotonic for ppi” while the code did otherwise is the same drift that produced this page's stale step numbering.

Two design choices worth flagging

1. Clipping at apply time, not just fit time. This corrects calibration.json files written before the change without a refit: the existing ppi-biobert-re spec yields 0.0010 / 0.9990 instead of hard 0.0 / 1.0 the moment the code loads it. Verified against the unmodified file on disk. Clipping only at fit time would have left the shipped checkpoint asserting certainty until someone retrained it on a GPU.

2. rank keeps the score a probability. It changes only which model's verdict represents a corroborated pair, comparing each score against its own model's distribution. The kept value is still the winner's calibrated probability, so --score, --thresholds and the browser slider all keep their meaning. The alternative — storing the percentile itself as score — would have put a number that is not a probability behind thresholds that assume one.

Measured effect

Cross-model bias on the same unchanged input file: 65/4 → 55/14 PPI/BioRED across the 69 corroborated pairs — 6% to 20% for BioRED. Not parity, and it should not be: the rank rule removes the calibrator's thumb on the scale, not PPI's genuine edge. The graph is unchanged at 157 nodes / 235 edges; the exports moved 112 → 111 (M) and 219 → 217 (G) triples at ≥0.8. Section 6 has the full table.

The ceiling check earned its place on the first run:

!! score>=0.95 is unreachable for biored-biobert-re -- that cutoff is effectively ppi-biobert-re-only
!! score>=0.99 is unreachable for biored-biobert-re -- that cutoff is effectively ppi-biobert-re-only

Those two stops have been gene-only in every prior run with nothing saying so.

One bug found and fixed during implementation. The ceiling check first read the post-merge triples, which mis-attributes scores: after the merge a pair keeps the typed model's name in predicate.model but may carry the other model's number, so BioRED appeared to have a ceiling of 1.0000. It now reads the pre-merge file, which reports the true 0.9022. The wrong version would have silently suppressed the very warning the recommendation asked for.
